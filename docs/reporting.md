# Отчёты миграции

Команда `report` формирует Markdown или JSON по сохранённому UUID. Она открывает target в режиме чтения и работает с загруженными, проверенными и прерванными запусками. Для текущей версии нужна ревизия `target_0005`, которую применяет `migration-pipeline init`.

```bash
uv run --locked migration-pipeline report --run-id "$RUN_ID"
uv run --locked migration-pipeline report --run-id "$RUN_ID" --output migration-report.md
uv run --locked migration-pipeline report --run-id "$RUN_ID" --format json --output migration-report.json
```

По умолчанию Markdown выводится в stdout, а структурированное событие пишется в stderr. `--output` создаёт новый файл. Код `0` означает, что отчёт сформирован, `1` означает ошибку чтения или записи, `2` — неверные параметры или настройки. Статус самой миграции входит в отчёт.

| Показатель | Как рассчитывается |
| --- | --- |
| Исходных записей | Берётся из сохранённой верификации или завершённой загрузки. Для прерванного запуска читается по UUID зафиксированного снимка. При недоступном снимке JSON содержит `null`, а Markdown показывает «Недоступно». |
| Успешно перенесено | Сумма вставленных, обновлённых и неизменённых исходных записей. Отклонения показываются отдельно. |
| Ошибки и повторы | Суммы записей журналов target с разбивкой по коду ошибки, признаку карантина, операции и причине повтора. |
| Длительность и скорость | Время от создания запуска до окончания загрузки или момента чтения отчёта. После `resume` интервал включает паузу между процессами. Скорость равна числу обработанных строк, делённому на длительность. |
| Пиковый RSS | Максимум операционной системы в байтах среди процессов `migrate` и `resume` на macOS и Linux. Измерение сохраняется вместе с контрольной точкой, а при завершении пишется последняя доступная величина. Запуски без записанного замера показывают `NOT_MEASURED`. |
| Верификация | JSON включает сохранённый результат с денежными расхождениями, внешними связями и SHA-256. Markdown показывает дату и итоги обязательных проверок. |

Временные отметки берутся из PostgreSQL. После успешной загрузки отчёт можно сформировать при недоступной legacy. Повторный экспорт отражает последнее сохранённое состояние target.

## Графики бенчмарка

Для графиков нужен `results.json`, созданный командой `benchmark`.

```bash
uv run --locked --extra charts migration-pipeline benchmark-charts \
  --results benchmarks/6fde1748-c887-4ba2-8776-da5a6887043b/results.json \
  --output benchmark-small.png
```

PNG содержит медиану пропускной способности, распределение времени партий, пиковый RSS процесса CLI и скорость отдельных партий. Для графика скорости используется первый измеряемый успешный прогон каждой стратегии. По оси X накапливается измеренное время партий. Временные промежутки между ними идут в общий замер прогона. Графики строятся по подтверждённым измеряемым прогонам. При отсутствии данных команда возвращает `NOT_MEASURED`. [Методика и результаты бенчмарка](benchmarking.md).
